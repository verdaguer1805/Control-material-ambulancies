Implementation:
- Cache only a server-confirmed auditor profile. Require matching local role,
  authenticated identity marker, full name, lot, zone and warehouse scope.
- A network/timeout failure retains local review permission, not upload rights.
  An explicit inactive/revoked/mismatched profile removes the offline cache and
  blocks editing. No first-time offline authorization or offline zone changes.
- Every answer/note persists synchronously to the existing local audit store.
  Resuming merges local and server pending drafts without discarding newer work.
- Offline beginning preserves a stable audit UUID and original profile revision.
- Submit freshly verifies profile and warehouse, registers/saves that same UUID,
  then calls the existing idempotent submit RPC. A failed send keeps a durable
  pending-send marker, centered warning and manual Reintentar envio button.
- Pending does NOT mean received. Only server received_at marks an audit sent.
- No automatic sending in the background is promised. The OS may suspend the
  app; saved drafts recover on reopening and the auditor manually retries.
- Material consumption remains separately server-verified. No offline stock
  decrement. Existing unit/supervisor behavior is unchanged by default props.
