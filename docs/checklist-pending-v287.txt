Release v287 - 2026-11-27

Persistent checklist send warnings
- SVB and BP save the attempt before HTTP. Closing or reopening does not erase it.
- A centred warning can be acknowledged; the persistent notice remains until a
  valid server receipt confirms the matching attempt.
- Separate lot, zone, unit, vehicle, guard and checklist family. An expired guard
  stays visible as unconfirmed; it is not reassigned or resent as a new guard.
- SVB/BP retry uses the existing send action and backend identity. No new
  automatic resend or extension of backend guard deadlines.
- TSNU retains its existing ordered outbox and automatic retry, now requiring
  checklist_submitted_at before removing a checklist operation.
- Failed edited resends cannot display the previous confirmation as confirmation
  of unsent changes. Storage errors do not erase answers or trigger fresh sends.
